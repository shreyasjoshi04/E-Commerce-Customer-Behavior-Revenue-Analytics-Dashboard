# 🛒 E-Commerce Customer Behavior & Revenue Analytics Dashboard

End-to-end data analytics project on **11.7K+ e-commerce transactions**: data cleaning in Python, business
analysis in PostgreSQL, **RFM customer segmentation**, churn & cohort analysis, and a KPI-driven **Power BI** dashboard.

**Tech stack:** Python (Pandas, NumPy, Matplotlib) · SQL (PostgreSQL) · Power BI · Jupyter · Git

> ⚠️ The dataset is **synthetic** (generated by `scripts/01_generate_raw_data.py`, seed 42) to simulate an Indian
> online retailer. It contains deliberate data-quality issues so the cleaning workflow is realistic.

---

## 🎯 Business Questions
1. How is revenue trending and how strong is seasonality?
2. Which categories, cities, age groups and payment methods drive revenue?
3. Who are our best customers, and who is about to churn?
4. How do discounts affect order value?
5. What are the repeat-purchase and churn rates, and how much revenue is at risk?

## 🧹 Data Cleaning (raw → clean)
| Issue | Fix |
|---|---|
| 210 exact duplicate rows | `drop_duplicates()` |
| Mixed date formats (`YYYY-MM-DD`, `DD/MM/YYYY`) | Parsed with explicit formats, asserted no nulls |
| Inconsistent casing / whitespace in categorical columns | Strip + mapped to canonical labels |
| Missing age / city / payment method / discount | Customer's other orders first → median (age), mode (payment), 0 (discount), "Unknown" (city) |
| 25 invalid quantities (≤ 0) | Removed |
| Feature engineering | `gross_amount`, `discount_amount`, `revenue`, `realised_revenue`, month/quarter/age group |

Result: **11,775 clean rows, 0 nulls**, 24 months (Jan 2024 – Dec 2025).

## 📊 Key Results
*Realised revenue = net order value (after discount) of **Delivered** orders only.*

| KPI | Value |
|---|---|
| Realised revenue | ₹2.34 Cr (₹23.36M) |
| Delivered orders | 10,474 |
| Customers | 7,603 (7,050 with ≥ 1 delivered order) |
| Average order value | ₹2,231 |
| Repeat purchase rate | 33.1 % |
| Churn rate (no purchase in 90 days) | 63.3 % |
| Cancellation / return rate | 5.1 % / 6.0 % |

### Insights
- **Electronics** is the top category (30.6 % of revenue), followed by Home & Kitchen (23.6 %) and Fashion (21.4 %).
- **Festive seasonality:** Oct–Dec generate **42.5 %** of revenue → plan inventory, ads and discounts ahead of Q4.
- **Pareto effect:** the top 20 % of customers contribute **52.3 %** of revenue.
- **Champions** are 20.4 % of customers but **36.8 %** of revenue; **At Risk** customers hold 28.7 % of revenue and
  have been inactive for ~350 days on average → prime target for win-back campaigns.
- **UPI** is the most-used payment method (39.6 % of delivered orders).
- Only 33 % of buyers purchase twice → post-purchase engagement (loyalty points, replenishment reminders) is the biggest growth lever.

### Recommendations
1. Launch win-back offers for **At Risk / Needs Attention** segments (high past value, long inactivity).
2. Reward **Champions** with early access/loyalty tiers to protect 37 % of revenue.
3. Convert **New / Promising** one-time buyers with a second-purchase incentive within 30 days.
4. Build the Oct–Dec campaign calendar early; stock Electronics & Home appliances first.
5. Investigate categories with higher return rates (see SQL Q15).

## 🧮 RFM Segmentation
Recency (days since last delivered order), Frequency (delivered orders) and Monetary (realised revenue) are each
scored 1–5 by quintile (frequency ties broken by spend). Segment rules:

| Segment | Rule |
|---|---|
| Champions | R ≥ 4 and F ≥ 4 |
| Loyal Customers | R ≥ 3 and F ≥ 3 |
| New / Promising | R ≥ 4 and F ≤ 2 |
| Needs Attention | R = 3 and F ≤ 2 |
| At Risk | R ≤ 2 and F ≥ 3 |
| Hibernating | R = 2 |
| Lost | R = 1 (remaining) |

## 🗄️ SQL Analysis (PostgreSQL)
`sql/02_analysis_queries.sql` answers 16 business questions: KPIs, MoM growth (`LAG`), category share (window `SUM`),
top customers (`RANK`), repeat rate (subquery), frequency buckets (`CASE`), discount bands, seasonality,
**RFM in pure SQL (`NTILE`)**, churn, **cohort retention (CTEs)**, best category per city (`ROW_NUMBER`) and more.

## ▶️ How to Run
```bash

cd ecommerce-customer-analytics
python -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate

#   2. set PGUSER / PGPASSWORD (or edit the script), then:

#   3. run sql/02_analysis_queries.sql in pgAdmin / psql / DBeaver
```
